# Разбор внешнего ревью — 2026-09-06

Стратегическое замечание принимается: наличие архитектуры и проверок не
доказывает полезность памяти. Новые стадии инфраструктуры и массовый рефакторинг
не являются следующим шагом. Приоритет — качество извлечения, сохранение причин
текущих действий и проверка отложенных связей между действиями и наблюдениями.
Успешные полные SRE-прогоны и честное парное сравнение остаются обязательными.

Оба внешних ревью рассматриваются совместно; второе не отменяет первое.
Ревью проверены по текущему коду и замороженным входам попытки 4. Три независимых
подзадачи проверили retrieval, credit assignment/identity и maintenance/derived
модули; основной агент сверил выводы и проверил runtime. Исходное ревью и
подробные доказательства сохранены в `artifacts/external-review-2026-09-06/`.
Замечания не принимались как готовые факты. Работающий прогон не изменён.

## Что меняет приоритет работы

1. **Завершение baseline — ближайший результат, retrieval — дешёвая диагностика.**
   Новый полный запуск нельзя тратить на ещё одну конфигурацию без проверяемого
   основания ожидать завершения. Сначала фиксируем фактический прогресс и цену
   цикла, затем проверяем минимальное изменение исполнения; большие расширения
   lessons и общий рефакторинг отложены. В текущем профиле действуют
   базовое лексическое ранжирование и дополнительный лексический score с
   diversity по run ID. Семантический hybrid Stage 10 не включён. Его результат
   Hit@1 0,25 → 0,875 относится к 16 документам и восьми специально составленным
   запросам, а не к успешности агента. Выполнен offline shadow replay на
   фиксированных шагах 30/60/90/120 с точными исходными запросами и тем же
   доступным корпусом. Baseline selection точно воспроизведён 4/4 раза.
   Все 3320 допустимых пар кандидат/запрос прошли лексический фильтр; 62,35%
   пересечений дали токены только из JSON-ключей. Для выбранных записей доля
   ниже — 48,25–53,57%; причинность итогового ранжирования не установлена.
   Обработка 822–912 записей заняла 0,60–0,70 с на запрос в этой пробе.
   Hybrid не измерен: локальные файлы модели есть, runtime FastEmbed 0.8.0
   и зависимости отсутствуют. Другой embedder не подставлялся. Ноль LLM,
   embedding, сетевых и simulator calls. Подробности —
   shadow report (локальный файл: `artifacts/external-review-2026-09-06/retrieval-shadow/report.md`).
2. **Кратковременная память — подтверждена конкретная потеря.** Replay из
   замороженного кода совпал со всеми 40 реальными историями наблюдений.
   Исходная ошибка шага 13 вытеснена на шаге 20 при 8302 байтах; ошибка шага 28 —
   на шаге 37 при 8675 байтах. Лимит — 8000 байт, максимум записей — 24.
   Причина вытеснения установлена; влияние на правильность последующих удалений
   серверов не доказано. Кандидат — удержание выбранных агентом свидетельств
   незавершённых действий в прежнем бюджете, без написанных нами SRE-уроков.
3. **Отложенные связи — реальный пробел, но не готовая причинность.** Сейчас
   `objective_deltas` строятся только между соседними наборами метрик.
   `operation_links` сохраняются, но lessons их не используют. Нужна отдельная
   проверка связанного «до/после» с идентичностью операции, временным порядком,
   совпадающими метриками и полным provenance. Совпадение операции не доказывает,
   что именно она вызвала изменение. Существующие activation gates сохраняются.

## Identity gate и результаты

Отсутствующая immutable world identity блокирует **активацию проверенных derived
lessons**, но не raw episodic recall. В текущем корпусе завершённые, неуспешные и
прерванные прошлые эпизоды явно доступны как недоверенные свидетельства.
Подменять identity хешем OpenAPI, URL или seed нельзя. Можно исследовать полезность
такого опыта с честной неизвестной совместимостью, не объявляя его законом мира.

## Второе ревью: завершение задачи и «три нуля»

**Стратегическое возражение принимается.** Число тестов, документов и строк не
компенсирует отсутствие успешного полного baseline. Для оценки итоговой пользы
памяти нужно парное сравнение при одинаковом исполнителе, кратковременном
контексте, модели и бюджетах. Переход от диагностики памяти к завершению baseline
не означает отказа от north star: он создаёт измеримую основу для сравнения.
Микропробы сохранения/извлечения полезны и до baseline, но не заменяют его.

## Что можно взять у коллеги

В найденном `ak-agent` подтверждён контракт до 8 определений действий и суммарно
до 64 исполнений за один LLM-ответ. Исполнитель последовательно проходит очередь,
ведёт отдельные request ID и останавливает хвост при ошибке или при pending,
если модель указала зависимость следующего действия. Это полезный образец
механизма; автоматическое ускорение в 8–64 раза из него не следует. Кроме того,
его `observe()` сам собирает несколько HTTP-наблюдений за решение. Сравнивать
106 решений коллеги с 106 нашими HTTP-действиями напрямую нельзя.

Агрегат `ak-agent/experiments/results.json`, измеренный 2026-09-04, подтверждает
завершённый seed 42: **106 решений, uptime 99,5932%, 344127622,02 ₽**. Это Sol low,
`memory_enabled=true`, четыре `runtime_versions`, без указанной версии публичной
схемы. Это не результат без памяти, не неизменный runtime и не выполнение нынешнего
порога <50 млн ₽. При механическом применении нынешней шкалы такая стоимость
попадает в диапазон 50 баллов; это пересчёт, не балл, возвращённый тем запуском.

Короткий список заимствований:

1. **Малый список действий за ответ.** Отдельные результаты и лимиты исполнений,
   прекращение на ошибке/зависимом pending, без повторного исполнения всего списка.
   Это отдельный opt-in контракт для следующей пробы, ещё не включённый у нас.
2. **Сохранённое намерение запроса.** До отправки записываются ID и payload,
   после — результат; повтор с другим payload отвергается. Для нас это кандидат
   на восстановление после обрыва, с сохранением исходного бюджета и неопределённого
   результата. Не даёт разрешения возобновлять уже закрытые frozen attempts.
3. **Запрос к памяти из текущего плана.** У коллеги поиск получает план/теги и
   свежие наблюдения. Для универсального варианта проверяем один запрос из
   фактически написанного предыдущего решения и текущего summary, без JSON-имён
   полей и без вручную выбранных SRE-фактов. Корпус, ranking и бюджет неизменны;
   offline сравнение ещё не является доказательством пользы.

Результат этой пробы запроса (локальный файл: `artifacts/external-review-2026-09-06/query-shadow/report.md`):
baseline воспроизведён 4/4, единственный treatment изменил выбор 4/4, но выбрал
одни и те же две записи на всех четырёх входах. Число допущенных кандидатов не
сократилось; бюджет 8000 соблюдён. Ноль LLM/embedding/network/simulator calls.
Полезность и релевантность не установлены, production query не изменён.
Три ошибки подготовки до первого retrieval сохранены, конфигурационный поиск
и повторные варианты treatment не выполнялись.

Свежий thread раз в десять решений переносить не требуется: наш адаптер уже
изолирует модельные решения. Простые remember/recall, recent steps и observer
из `simple_agent` также уже представлены у нас. Полная замена памяти соседом
не обоснована; полезны конкретные механизмы на пути исполнения.

Подтверждённой серии полных успехов по текущей публичной цели нет. Попытки 1–3
сохранены как неуспешные/неполные; попытка 4 также завершилась с ошибкой. Обнаружен разрыв
календарного и монотонного времени: один request/result разделяют 1932 секунды,
при provider telemetry 15,54 секунды. Причина не установлена; соблюдение
календарного per-call лимита этим запуском не доказано. Введён внешний контроль
его исходного общего календарного дедлайна; watchdog не посылал сигнал: процесс
исчез до дедлайна. Это не изменение решений агента.

Внешнее закрытие попытки 4 (локальный файл: `artifacts/simulator-refresh-080-2026-09-06/terminal-adjudication-04.json`):
377 решений, 19,8611% недели, текущий uptime 99,78053%, 15677224,23 ₽,
13080900 модельных токенов (в том числе 8619520 cached input), без provider retries.
Это неполный запуск, не успех. Все 754 извлечённые записи прошли структурную проверку
ID, trust и отсутствия будущих событий текущего прогона; это не семантический аудит оракула.
Ошибка cleanup `sqlite3.OperationalError: database or disk is full` помешала сохранить
исходный итог: frozen `outcome.json` всё ещё содержит `running` и оставлен неизменным.
Первичная ошибка неизвестна. Базы сейчас целы, запросы выполняются; свободное место
после сбоя не доказывает состояние диска в момент сбоя. Осталось четыре полные попытки.

## Что уже исправлено и где текущее состояние

- Убрано ошибочное «physical deletion не реализован»: maintenance и отдельный
  deletion CLI описаны раздельно.
- RFC помечен как исторический источник проектного решения; его исходный
  Proposed не превращён задним числом в утверждённое решение.
- В guide явно записано применение complete-record history в живых попытках.
- В SRE adapter добавлена кратковременная история `advance_progress`: до 8 целых
  записей и 2500 UTF-8 байт, только публичные значения requested/applied/ratio,
  причина остановки, ID источника и время. Async summary показывает фактическое
  продвижение. Pending/failed не считаются завершением; повторный poll не добавляет
  прогресс. Непригодные метаданные явно помечены, а не превращены в выдуманные числа.
  Действия, stop guards, generic runner и frozen attempt 4 этим не изменены.
- Полный набор: **811 passed, 2 skipped**, Ruff и `git diff --check` прошли.
  Первый запуск набора обнаружил запрещённую зависимость simulator → memory store;
  вычисление hash перенесено на стандартную библиотеку, allowlist не ослаблялся.
  Replay доказывает доступность фактов и лимит размера, не улучшение решений.
- Единственный актуальный handoff — [HANDOFF.md](../../HANDOFF.md).
  Файлы `HANDOFF_*` сохраняются как архивы доказательств и не являются
  параллельными указаниями для текущей работы.

Большой рефакторинг, новые approval-механизмы и включение всех модулей сразу не
приняты. Следующее изменение должно пройти различающий эксперимент на активном
пути памяти. Shadow retrieval — диагностика выбора, а не замена требуемым полным
успехам и парному измерению пользы.

## Следующий механизм: ограниченный список действий

После закрытия попытки 4 реализован opt-in `SimulatorV2BatchDecision`: 1–4
типизированных действия за ответ, прежний single-action контракт остаётся default.
`max_steps` сохраняет смысл числа решений; отдельный `max_actions` ограничивает
суммарное число исполнений за запуск и виден модели. Каждый выполненный элемент
имеет собственный результат, transition ID и `action_index`; незапущенный хвост
не считается исполненным и не воспроизводится автоматически. Ошибка, terminal или
неподтверждённая операция прерывает список. Проверка проходит и через обёртку
`PrestartedEnvironment` реального CLI.

Time advance и finish в первой версии разрешены только отдельно. Это сохраняет
проверки времени на свежем предыдущем наблюдении. Для batch изменён только выбор
кардинальности в общем промпте и добавлено описание исполнения списка; SRE-эвристики,
чужие уроки или ответы на будущие события не добавлены. Кратковременная история
сохраняет результаты всего предыдущего списка, а не исключает их все как дубликат
одного `latest_result`. Новые optional поля учёта исключаются из legacy JSON при
отсутствии значений; историческая schema-проверка явно утверждает только точные
добавления, сохраняя прежние fingerprint остальных полей.

Это ещё не доказательство ускорения или полного успеха. Проба формата на двух
публичных non-SRE задачах готовится отдельно; пятая полная попытка не запущена.
Для будущей пары проверена композиция baseline (локальный файл: `artifacts/external-review-2026-09-06/no-memory-baseline-composition.md`):
тот же runtime, current store, запись переходов и короткий контекст, но `history=None`.
Это baseline без межпрогонного корпуса, а не без любой памяти. Обычный CLI
`--memory none` выключает другую часть pipeline и для такой пары не подходит.


Проверка реализации: **840 passed, 2 skipped**, Ruff чистый; независимый quick review
не нашёл подтверждённых дефектов. Проба формата (локальный файл: `artifacts/external-review-2026-09-06/batch-format-probe/report.md`)
завершила два вызова Terra medium: 2/2 ответа валидны, но весь публичный целевой
результат предложен лишь в 1/2. Во втором ответе модель выбрала одно действие
вместо двух. Потрачено 29498 токенов, 14,367 секунды; simulator calls — 0.
Поддержка формата подтверждена, надёжное использование batch и выигрыш не доказаны.
Пятая полная попытка ещё не запущена; для неё требуется новый harness, сохраняющий
отдельный учёт решений/действий и первичный итог до проверки корпуса.
