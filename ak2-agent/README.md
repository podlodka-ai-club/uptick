# AK2 Agent

Универсальный агент с Codex SDK по подписке ChatGPT. Получив задачу, он выбирает
мир по каталогу, выполняет его начальную команду и **сам пишет интеграцию**:
скрипты, скилы и промпты. Ядро не знает API, метрик или стратегии конкретного мира.

Под наблюдением завершён полный недельный Uptick-прогон с uptime 99,5958%.
[Подтверждение, применение памяти и оценка автономности](worlds/uptick/experiments/supervised-result.md).
Запуск сопровождался исправлениями и возобновлениями; работа неизменной версии
без вмешательства ещё не проверена серией полных запусков.

## Запуск

Нужны Python 3.12+, `uv`, вход в Codex через ChatGPT и системная песочница:
macOS `sandbox-exec` либо Linux `bubblewrap`. В режиме без песочницы скрипты
не запускаются. На Linux потребуется разрешение на пользовательские namespaces.

```bash
cd /Users/aigizk/projects/uptick/ak2-agent
./run.sh --login
./run.sh --check-auth
./run.sh worlds

# Выбор мира по тексту делает модель:
./run.sh run "Пройди Uptick с целевым uptime и минимальной стоимостью" --seed 42

# Явный выбор удобен для экспериментов:
./run.sh run --world uptick --seed 43 --max-steps 3
./run.sh resume --world uptick
```

Модель по умолчанию — `gpt-5.6-sol`, effort `low`. Выбранный effort сохраняется
также при адаптации и периодическом пересмотре. Доступные модели показывает `./run.sh models`.
`--model`, `--effort` и `CODEX_MODEL` позволяют изменить выбор. `run.sh` исключает
API-ключи из окружения; SDK проверяет тип аккаунта `chatgpt`. Используется установленный
Codex CLI, если доступен, либо runtime SDK; `CODEX_BIN` задаёт конкретный бинарник.

## Два разных вида памяти

```text
ak2-agent/
  AGENTS.md                    каталог существующих папок миров
  prompts/                     общие промпты: выбор, адаптация, решение, объяснение
  src/ak2_agent/               универсальное ядро, изменяемое разработчиком
  worlds/<world>/
    AGENTS.md                  описание + начальная команда, заданные человеком
    knowledge/                 знание мира, создаваемое самим агентом
      scripts/adapter.py       протокол и API, без выбора стратегии
      skills/operate/SKILL.md  как вызвать средства работы с миром
      prompts/world.md         цель и правила мира
      references/             описание протокола
    .local/
      experience.sqlite3      опыт: уроки, подтверждения, противоречия, теги
      runs/<id>/              состояние отдельного запуска
        knowledge/             зафиксированная версия интеграции
        io/                    bootstrap, локальное состояние и секреты скрипта
      train-*/                результаты обучения
      evaluate-*/             замороженные знания и отдельные базы каждой группы
```

**Знание мира** — способы взаимодействия и документированные правила. **Опыт** —
условные выводы из реальных действий и их результатов. Опыт не подмешивается
в базовые скилы и промпты: адаптация не получает уроки или историю прошлых запусков.
Выученные процедуры хранятся как навыки в памяти опыта; модель применяет их,
подставляя текущие данные в действия. Ядро не исполняет текст уроков как Python.
Скилы мира могут механически выполнять явно выбранный моделью план: проверять
предусловия, отправлять заданные действия, ждать результат в пределах бюджета
и сохранять журнал для продолжения. Новые стратегические решения остаются модели.
Она получает измерения последнего решения — время и токены — вместе с длительностью
наблюдения, чтобы учитывать стоимость лишних возвратов к LLM.
Каждое подтверждение связано с точной версией утверждения и процедуры. При
обновлении старой базы счётчики без такой привязки сохраняются как история,
а уроки получают статус кандидатов и время на повторную оценку. Модель может
заново оценить доступный старый факт относительно текущей формулировки один раз.
Повтор той же оценки не укрепляет урок; изменение формулировки требует нового ключа.

Все локальные данные конкретного мира принадлежат его папке. Чтобы агент забыл мир,
останови его активные процессы и удали или вынеси `worlds/<world>/` из каталога.
При следующем запуске папка не обнаружится, её память не загрузится; другие миры
сохранят свои знания и опыт. Общей базы с копиями специфичных уроков нет. В этой
версии сознательно нет переноса уроков между мирами. Корневой AGENTS.md указывает
команду получения актуального каталога и не хранит копии паспортов. Внешний сервер симуляции и
история самого провайдера LLM не являются локальной памятью этого приложения.

## Подключить неизвестный мир

Достаточно создать `worlds/<id>/AGENTS.md` с блоком `world`, например через команду:

```bash
./run.sh add-world example \
  --description 'Что это за среда и какие задачи к ней относятся' \
  --bootstrap 'curl --no-buffer -sS https://example.org/agent-passport' \
  --replay-safe
```

`--replay-safe` указывай только если начальная команда безопасно повторяется:
это чтение или API гарантирует идемпотентность по одному request_id.
Для мутаций начальная команда получает стабильный `$AK_REQUEST_ID` и `$AK_SEED`.
Поля `defaults` и `--options '{"origin":"..."}'` становятся переменными
`AK_ORIGIN` и т. п. `--origin` — удобное сокращение для этой настройки.
Команда должна вывести один JSON-документ. Для `curl` полезен `--no-buffer`:
некоторые серверы отдают документ без немедленного закрытия соединения.

```bash
./run.sh adapt --world example --seed 1   # только изучить API, не накапливать опыт
./run.sh run --world example --seed 2    # адаптация также выполняется автоматически
```

Паспорт — доверенная конфигурация пользователя, его shell-команда исполняется
в песочнице. Неизвестный или неоднозначный запрос не запускает случайный мир.
Нужно дополнить описание либо явно указать `--world`. Начальные команды двух
готовых примеров находятся только в их папках:
[Uptick](worlds/uptick/AGENTS.md) и [Pantry](worlds/pantry/AGENTS.md).

Адаптация идёт итерациями: модель создаёт файлы → проверка синтаксиса → реальный
`observe` в песочнице → диагностика модели → следующая версия. После проверки
интеграция публикуется в knowledge. Контракт объясняется в [prompts/contract.md](prompts/contract.md).
Новая интеграция проверяет наблюдение; корректность всех её будущих управляющих
команд этим ещё не доказана. При ошибке исполнения обычный обучающий запуск может
сам исправить адаптер (до двух ремонтов); замороженные эксперименты его не меняют.
Если интеграция работает, но нужного способа наблюдения или действия ещё нет,
модель запрашивает расширение через `adaptation_request`. Она сама изменяет только
knowledge этого мира; небольшие изменения передаются точными патчами. Исходный
запрос и неопубликованный черновик сохраняются между попытками и рестартами.
Ошибка отдельного источника передаётся модели вместе с доступными данными,
чтобы временный таймаут не вызывал бесконечное переписывание исправного скрипта.

## Команды из ak-agent

```bash
./run.sh run --world uptick --seed 42
./run.sh run --world uptick --seed 43 --no-memory
./run.sh resume --world uptick
./run.sh memory --world uptick
./run.sh memory --world uptick --knowledge --json
./run.sh ask --world uptick "Что ты запомнил и как это меняет твои действия?"
./run.sh report --world uptick
./run.sh models
./run.sh train --world uptick --seeds 11,12,13 --jobs 2
./run.sh evaluate --world uptick --seeds 101,102 --jobs 2
```

Вызов без команды открывает консоль вопросов, `--world` выбирает память.
Вопросы также можно передавать напрямую: `./run.sh --world pantry 'Что ты знаешь?'`.
`/exit` завершает диалог. Каждый вопрос получает актуальный снимок памяти;
скрытой долговечной истории чата, объединяющей миры, нет.

`--no-memory` отключает извлечение и обучение опыта, сохраняя knowledge, текущий
план и checkpoint. Режим сохраняется при resume. `--max-steps` ограничивает текущий
процесс, а не срок мира; достижение лимита даёт `paused`, не победу. `resume`
сохраняет модель/effort, если они не переопределены явно. Ctrl+C сохраняет очередь.

## Саморефлексия после каждой остановки

После завершения мира, лимита времени или шагов, ошибки, запроса остановки,
Ctrl+C и SIGTERM ядро сохраняет checkpoint и запускает отдельный разбор.
Он анализирует только фактически пройденный участок: незавершённый мир не считается
победой или поражением. Управляющие действия и очередь остаются неизменными.
Первый Ctrl+C останавливает основную работу и запускает разбор; повторный Ctrl+C
во время разбора приостанавливает уже его. При SIGKILL, падении процесса или
отключении питания выполнить LLM-вызов невозможно: метка незавершённой попытки
сохраняется заранее, и следующий `resume` сначала разбирает её, затем продолжает мир.

Саморефлексия не зависит от оставшегося времени основной работы. На подготовку
доступа к истории отводится до 300 секунд, на сам анализ — ещё до 300 секунд.
Подготовка не расходует время анализа. Лимиты: до 8 решений, 6 исторических чтений,
2 попыток подготовки интерфейса и 3 проверок источников. Уже начатый вызов модели
может завершиться за границей дедлайна; готовое решение сохраняется, но следующий
вызов после дедлайна не начинается. Ошибка или прерывание разбора оставляет его
возобновляемый checkpoint и не изменяет исходный результат основной работы.

События и факты больше не обрезаются до последних 150/200 записей. В SQLite мира
сохраняется полный архив каждого запуска; обычный контекст модели остаётся коротким.
Саморефлексия получает индекс архива и может читать ранние события через локальный
источник `__local_events__` (курсор `after_id`, `limit` 1–50, необязательный `kind`).
Чтение ограничено снимком на момент начала разбора; события самого разбора не
сдвигают пагинацию. Архив возвращает исходные ID фактов, не создавая новых подтверждений.
Локальные и внешние чтения разделяют общий лимит шести запросов. Успешное локальное
чтение не устанавливает `verified_history`, который обозначает только внешнюю историю.
Старые запуски помечаются `complete_from_creation=false`: удалённые ранее решения
не восстанавливаются. Хранятся 100 последних завершённых и разобранных запусков;
запуски с незавершённой саморефлексией не удаляются этой политикой.

Перед каждым обновлением урока при работе агента, разборе ошибки или саморефлексии
выполняется отдельный LLM-вызов `verify_lesson` с исходными фактами и контекстом
(включая фильтры исторических запросов). Он проверяет утверждение, существенные
пункты процедуры и соответствие verdict доказательствам. Общая победа, принятие
команды и совпадение с фильтром выборки сами по себе недостаточны. При отказе,
ошибке проверки или истёкшем бюджете память не подкрепляется; причина остаётся в
`learning_feedback`. Результат проверки сохраняется до записи урока, повторное
применение использует прежние идентификаторы и существующую дедупликацию.
Проверка использует ту же модель/effort в отдельном контексте, до 60 секунд в пределах
бюджета текущей фазы. Это дополнительная проверка моделью, а не формальное доказательство.
Ранее сохранённые подкрепления автоматически не пересматриваются.

Ядро всегда предоставляет сохранённые решения, наблюдения и реальные факты.
Дополнительно отдельный `scripts/history.py` проверяет документированные источники
истории текущего мира. При необходимости модель готовит этот читатель в отдельной
копии knowledge запуска, без изменения рабочей интеграции. `supported`,
`unsupported` и `unavailable` различают поддержку истории и временную недоступность.
Отсутствие истории, таймаут или ошибка подготовки не отменяют разбор локальных записей.
Уроки требуют реальных `evidence_ids`; отсутствие доказательств означает пустой
список уроков, а не выдуманный опыт. Повторное чтение события не повышает уверенность
повторно. Непроверенные объяснения сохраняются только в `hypotheses` отчёта.
`--no-memory` и `evaluate` тоже получают отчёт, но обучение остаётся выключенным.

Разбор использует только отдельный интерфейс `discover/read`, никогда `adapter.py act`.
Нельзя продвигать время, восстанавливать pending-операции, выполнять probe или
проверять альтернативную стратегию. Это относится и к незавершённому миру.
Наблюдательная семантика удалённых запросов определяется документированным протоколом;
сама файловая песочница не доказывает отсутствие побочных эффектов произвольного API.
Подробности — в [контракте истории](prompts/history-contract.md).

Для разбора сохранённой остановки без продолжения игры:

```bash
./run.sh reflect --world uptick LOCAL_ID
./run.sh report --world uptick
./run.sh ask --world uptick 'Какие выводы и гипотезы дал последний разбор?'
```

`reflect` продолжает незаконченный разбор в новом ограниченном окне; счётчики
чтений и решений сохраняются. Завершённый разбор той же остановки не повторяется.
После следующей основной попытки создаётся новый отчёт. `resume` сначала завершает
незаконченный разбор, а затем продолжает незавершённый мир. Если разбору опять не
удалось завершиться, управляющий цикл не запускается. У завершённого мира `resume`
занимается только разбором. `stream` может перейти к следующему завершённому миру,
оставив незаконченный разбор для отдельного `reflect`.

Текущий статус доступен в `retrospective`, причина остановки — в `termination`.
Отчёты и страницы лежат в `.local/runs/<id>/retrospective/<checkpoint_id>/`;
предыдущие отчёты перечислены в `retrospective_history`. Старые отчёты без
checkpoint_id также поддерживаются. Итог и очередь основной работы не переписываются.

`--time-budget-seconds 3600` задаёт час реального времени с создания run, включая
bootstrap, адаптацию, обращения к модели, исполнение и паузы между процессами.
Модель получает оставшееся время; оно обновляется и при чтении контекста частями.
После дедлайна запуск сохраняется как `paused` с `pause_reason=time_budget_exhausted`.
Уже начатый вызов SDK или скрипта не обрывается: его завершение может выйти за дедлайн,
но новые управляющие вызовы и действия не запускаются. Затем начинается саморефлексия
со своим бюджетом. Очередь и подтверждённые результаты сохраняются.
Это управляемая остановка на безопасной границе, а не жёсткое ограничение времени процесса.

```bash
./run.sh run --world uptick --seed 91 --model gpt-5.6-sol --effort low \
  --time-budget-seconds 3600 --max-steps 500 \
  --task 'Заверши весь мир с итоговой оценкой не ниже 50 баллов, выполнив обязательные требования.'
```

Обычный `resume` сохраняет исходный дедлайн, в том числе уже истёкший.
Явный `resume --time-budget-seconds 3600` назначает новый час с момента возобновления.
Без флага новый запуск не имеет временного бюджета. Значение — положительное целое.
Для `train`/`evaluate` бюджет применяется отдельно к каждому запуску с момента его
создания; для `stream` — к каждой новой задаче, с возможным переопределением через
поле `time_budget_seconds` строки JSONL. Повторное чтение потока не обновляет дедлайн.
Uptick учитывает реальное время и продолжает идти между запросами.
При изменении ядра или общих промптов работающий процесс сохраняет checkpoint
на границе действий или итераций адаптации; `resume` загружает новую версию.
Модель получает актуальное состояние, результаты недавних действий и прежние
метрики. Большие контексты передаются ограниченным обзором с JSON Pointer
указателями: модель может прочитать нужные поля, страницы коллекций или фрагменты
текста через `context_read`. Справочники `references/` первоначально передаются
описателями и читаются по необходимости. Полный исходный контекст сохраняется
на время вызова в его изолированной рабочей папке. Чтение не обращается к миру
и не создаёт фактов опыта. Основным инструкциям и актуальному наблюдению выделены
отдельные бюджеты, чтобы большая история не вытесняла формат инструментов.
За одно обращение можно запросить до шести страниц. Последняя страница и ранее
прочитанные фрагменты сохраняются в пределах отдельного бюджета, вместе с рабочими
заметками модели. При переполнении вытесняются старейшие фрагменты; оригинал доступен
для повторного чтения. Поэтому каждое решение не требует заново читать весь справочник.
Перед отправкой проверяется консервативный размер всего подготовленного конверта
(с инструкциями и схемой): максимум 800000 символов с учётом Unicode-экранирования.
На решение допускается 24 дополнительных чтения; исчерпание бюджета сохраняет
checkpoint вместо неограниченного цикла. В логе `brain_request` видны начало
обращения и размер контекста, в `context_read` — выбранная страница.
Повторные полные копии старых снимков остаются в журнале,
но не увеличивают каждый запрос к LLM. Структурная сводка выделяет даты и пагинацию
наблюдений без знания предметной области.
Точные дубликаты крупных значений заменяются JSON Pointer ссылками на первую
копию в том же контексте. Содержимое остаётся полностью доступным; преобразование
проверяется на обратимость. Лог `brain_usage` содержит исходный/переданный объём,
время ответа и фактические счётчики потребления SDK.

`train` собирает общий опыт выбранного мира, поддерживает `--models`, `--jobs`,
`--strategy` и разные seed. Сначала нужно выполнить adapt. В `evaluate` используются
новые seed, отсутствующие в обучении: одни и те же версии knowledge, замороженный
опыт против пустого опыта, обучение выключено у обеих групп. У каждой своя база.
Метрики определяет адаптер мира, отчёт не содержит зашитых полей SRE.
Процессы не используют общий контекст LLM. Равный seed не устраняет вариативность
модели или реального времени; преимущество памяти нужно измерять, а не предполагать.

Чтобы продолжить отдельную экспериментальную группу:

```bash
./run.sh resume --world pantry LOCAL_ID \
  --memory /полный/путь/ak2-agent/worlds/pantry/.local/evaluate-ID/m0-101-experience.sqlite3
```

`--memory` допускается только внутри `.local` выбранного мира, чтобы случайно
не использовать опыт другого мира. Данные старого `ak-agent` автоматически не импортируются.

## Поток задач

`stream` читает JSONL последовательно; задача может сама указать мир или выбрать его
через текст. После паузы повторный запуск того же файла продолжает сохранённый run.
Изменение уже выполненной строки обнаруживается и требует нового файла-источника.

```jsonl
{"task":"Накорми персонажа в учебной кухне","seed":31}
{"task":"Пройди Uptick","seed":32,"world":"uptick"}
```

```bash
./run.sh stream tasks.jsonl --max-steps 250
```

## Журнал изменений памяти

`lesson_changes` в SQLite выбранного мира — постоянный журнал с датой UTC,
ID запуска (или null для ручного обслуживания), ID урока, типом события и причиной.
Он различает `added`, `reinforced`, `contradicted`, `rejected`, `deleted`.
Сохраняются полный текст и процедура, состояние до/после, счётчики и уверенность,
предложение модели, факты и заключение проверки. При удалении сохраняются также
подтверждения и пороги забывания; причины `capacity_limit` и
`weak_and_low_importance` различаются. Противоречие снижает доверие, но само по себе
не означает удаления. Повтор уже учтённого факта фиксируется как `rejected`,
не как новое подкрепление.

Изменение урока и запись в журнал коммитятся одной транзакцией. Удаление урока,
его подтверждений или старого run не удаляет этот журнал. Лимита автоматической
очистки журнала нет: объём базы будет расти. Обычные чтения памяти и счётчик её
использований отдельно не журналируются. При первом открытии существующей базы
добавляются `snapshot` текущих уроков; прошлые добавления и удаления не выдумываются.
Копирование опыта в новую экспериментальную базу отмечается как `imported`, без
переноса журнала исходного запуска.

Просмотр не вызывает LLM и не запускает обслуживание памяти:

```bash
./run.sh memory-history --world uptick
./run.sh memory-history --world uptick --change deleted
./run.sh memory-history --world uptick --lesson LESSON_ID --json
./run.sh memory-history --world uptick --run-id LOCAL_RUN_ID --json
```

Выдача идёт от старых записей к новым. `--limit` задаёт размер страницы (1–1000,
по умолчанию 50), `--after-id` продолжает после указанной записи. JSON содержит
полные поля и `next_after_id`; при продолжении сохраняйте выбранные фильтры.

## Как формируется опыт

| Слой | Правило |
| --- | --- |
| Паспорт и рабочая память | Сохраняются сразу после получения; не забываются в активной задаче |
| Эпизоды | Полный архив событий и фактов; короткий контекст модели читается отдельно |
| Кандидат | Новый условный урок с подтверждённым фактическим основанием |
| Долговременный урок | Минимум 3 подтверждения и доверие ≥75% |
| Навык | Такой же подтверждённый урок с процедурой применения и проверки |
| Забывание | Ослабление без новых подтверждений, удаление слабого неважного опыта и предел 80 уроков |

Доверие: `(support+1)/(support+against+2)`. Это счётчик подтверждений, не
откалиброванная вероятность. Повторный опрос той же операции не даёт новый факт;
несколько доказательств в одной рефлексии дают одно подтверждение. Факт ошибки
нельзя использовать как успех. Урок может быть опровергнут, а ранее сильный навык —
снова стать кандидатом. Чтение и `uses` не укрепляют память.
Модель получает `learning_feedback` с объяснением отклонённых записей, включая
фактический outcome процитированных доказательств. Успешно выполненная команда
может опровергать урок о её ожидаемом эффекте; оценка урока и outcome факта различаются.
Смысл урока под существующим ключом не переписывается. Изменённое утверждение или
процедура получает новый ключ и начинает как кандидат, без старого счётчика уверенности.
Измеренные исходы диагностических испытаний могут быть фактами опыта, даже если
они не меняют мир; успешная доставка запроса сама по себе таким доказательством не является.

Сила уменьшается экспоненциально по циклам обучения. Период полураспада:
`30 + 20*support + 100*importance`. Неважные уроки с силой <0.12 забываются.
Завершённые обычные run ограничены последними 100; активные состояния сохраняются.
Архивы экспериментов и явно записанные консольные логи не удаляются автоматически.

Адаптер интерпретирует семантику результатов мира, а модель — значение опыта.
Ядро проверяет принадлежность фактов запуску, outcome и уникальность доказательств.
Оно не может математически доказать, что сгенерированный адаптер правильно понял
любой неизвестный API или что вывод модели причинно верен. Основания и противоречия
поэтому доступны в `memory --json` и `ask`.

## Проверка и демонстрация

```bash
# Без сети и вызовов LLM:
uv run --project . python -m unittest discover -s tests -q

# Реальные проверки системной песочницы (запускать из обычного терминала):
AK2_SANDBOX_TEST=1 uv run --project . python -m unittest discover -s tests -q

# Независимый учебный HTTP-мир:
./.venv/bin/python worlds/pantry/environment/server.py
# В другом терминале:
./run.sh run 'Накорми персонажа в учебной кухне' --seed 21
```

Учебный сервер реализует сам мир, а не стратегию агента. Его состояние находится
в `worlds/pantry/.local/environment.json` и переживает перезапуск. Агент не видит
исходников сервера; knowledge обоих примеров было создано им через SDK.
Установленные knowledge можно сохранить при очистке `.local` для новой демонстрации
обучения; сначала останови активные запуски и учебный сервер.

Протокол SDK проверен по [официальной документации](https://learn.chatgpt.com/docs/codex-sdk)
и установленной версии `openai-codex==0.147.0`. Все общие промпты находятся
в `prompts/`, предметные — в папках knowledge соответствующих миров.

В текущей проверке прошли **77 тестов**, включая реальную песочницу macOS,
повтор идемпотентных запросов и восстановление незавершённой адаптации.
Параллельные адаптации одного мира ждут освобождения блокировки и используют
последнюю опубликованную версию knowledge. При возобновлении старого черновика
модель получает его отдельно и объединяет с изменениями другого запуска.
Если папка мира удалена во время ожидания, процесс прекращается и не создаёт её заново.
Агент может запросить паузу с причиной, когда проверенное внешнее препятствие
мешает продолжить работу. План и checkpoint сохраняются; пауза не означает
завершение мира или успех. Причина доступна в `report`, продолжение — через `resume`.
Пауза доступна также во время адаптации: черновик сохраняется, блокировка
освобождается, непроверенная версия знания не публикуется. При возобновлении
ядро заново проверяет доступный адаптер и передаёт модели
свежий результат вместо сохранённой ошибки. Исходный запрос на изменение
интерфейса и диагностика незавершённого действия сохраняются.
После остановки или исчерпания адаптации агент делает отдельный разбор для памяти без действий
в мире. Системный факт описывает только сбой выполнения агента, а не итог мира
или причину серверной ошибки. Повтор того же инцидента на одном шаге не усиливает
урок заново; режим без опыта пропускает разбор. Ошибка модели при разборе сохраняет
исходную причину остановки. Команда `ask` учитывает разборы успешных и неудачных запусков.
Временная перегрузка выбранной модели повторяется не более трёх раз с тем же
контекстом и той же моделью; при устойчивой ошибке сохраняется checkpoint.
Потерянный ответ на действие проверяется до трёх раз с исходным request_id,
только если действие явно помечено replay_safe. После трёх неопределённых ответов
агент получает исходный запрос и диагностику для исправления интерфейса в пределах
общего бюджета ремонтов. Затем допускается одна проверка того же запроса.
При повторном отказе очередь остаётся сохранённой; небезопасные действия
не повторяются, замороженное knowledge проверочного запуска не меняется.
Для чистого чтения адаптер может явно вернуть `delivery=read_failed`: ошибка и
неполнота сохраняются, остаток пакета отменяется, управление возвращается модели.
Она сама выбирает новый запрос. Такой результат не подтверждает эффекта и не
подходит для мутации с потерянным ответом; ядро запрещает сочетать его с фактами
эффектов, успехом, завершением мира или незавершённой операцией.
Подробности живых запусков: [сценарий демонстрации](DEMO.md),
[кухня: обучение и парная проверка](worlds/pantry/experiments/results.json),
[кухня: поток задач](worlds/pantry/experiments/stream-results.json),
[Uptick: ограниченные прогоны](worlds/uptick/experiments/results.json),
[Uptick: наблюдение за полными прогонами](worlds/uptick/experiments/supervision.md).
На первоначальной проверке Uptick выполнены 17 обучающих решений с самостоятельным ремонтом интеграции
и два проверочных запуска по 2 решения. Все остановились с checkpoint;
полное прохождение недели и итоговый SLO этими прогонами не установлены.

При временном сбое Codex SDK (обрыв потока/соединения, таймаут,
перегрузка или временная недоступность сервиса) ядро автоматически продолжает
тот же запуск из checkpoint. Задержки: 5, 10, 20, 40, затем 60 секунд;
число попыток не ограничено, пока не истечёт `time-budget-seconds` или не
поступит остановка. Ожидание входит в бюджет времени. В логах видны
`recovery_wait` (причина и задержка) и `recovery_resume`.
Соединение SDK пересоздаётся, модель и effort сохраняются, очередь и ID
запросов восстанавливаются из памяти. Блокировка запуска удерживается и во
время ожидания. Ctrl+C останавливает восстановление. Ошибки конфигурации,
неопределённый результат небезопасной операции и осознанная пауза модели
не запускают этот механизм автоматически.

Ошибки ответа модели также восстанавливаются автоматически: некорректный JSON
(включая `Extra data`), нарушение схемы, пустой ответ, недопустимое сочетание
действий и паузы, исчерпание числа чтений контекста. Ответ целиком отклоняется
до выполнения действий; после ожидания ядро повторяет запуск из checkpoint.
Это правило применяется к ответам модели, а не к произвольному повреждению
локальных файлов или конфигурации.
