# Контракт скрипта мира, версия 1

Точка входа: `scripts/adapter.py`, Python 3.12+ и стандартная библиотека.
Запускается отдельным процессом. Его stdin — один JSON-объект:
`{"operation":"observe|act","action":{},"request_id":"...","seed":1,"task":"...","options":{}}`.
Текущая папка содержит `bootstrap.json` — оригинальный JSON-ответ начальной команды.
Эта папка изолирована для одного запуска. Можно сохранять здесь секреты,
незавершённые операции, кеш протокола, локальные данные и журнал транспорта.
Скрипт не может читать ядро, память уроков, другие запуски или другие миры.
Один вызов ограничен 120 секундами и 8 000 000 байт stdout+stderr. Это общий
бюджет всех запросов, повторов и обработки; оставляй время на сохранение состояния
и вывод JSON. Если часть источников не успела ответить, возвращай доступные данные
с явной диагностикой неполноты до истечения бюджета. Большой ответ дели на страницы.
Свои вспомогательные модули импортируй через явно добавленный каталог __file__.
Используй pathlib.Path(__file__) для поиска скилов и справочников внутри knowledge.

stdout — ровно один JSON-объект (все перечисленные поля допустимы):
```
{"data":{},"evidence":[],"done":false,"success":null,"metrics":{},
 "external_id":null,"pending":false,"error":null,"delivery":"known"}
```

- `observe` собирает наблюдение и статусы ранее запущенных операций, не выбирает
  стратегию и не выполняет управляющих действий. `act` исполняет ровно переданное
  моделью действие. Формат action определяешь сам по API и описываешь в скиле.
- Поля data и metrics произвольны и определяются миром. Возвращай достаточно
  точный протокол, каталог действий и наблюдения, чтобы модель могла решать задачу.
- done=true только если сам мир явно завершил задачу; success — его итоговая оценка.
  pending=true означает принятую асинхронную операцию, а не её завершение.
- error — строка или JSON-объект с ошибкой, которую модель должна оценить.
  Не скрывай отсутствие данных.
- delivery: known, если получен определённый ответ на действие (включая явный
  отказ API); unknown, если запрос мог выполниться, но ответ потерян; not_sent,
  если локальная проверка отвергла действие до отправки. Для unknown runtime
  сохраняет очередь и прежний request_id, не заменяя его новым действием.
  Ошибка без delivery и без факта явного отказа консервативно считается unknown.
- delivery=read_failed, если по документированному протоколу действие только читает
  данные, не запускает операции и не меняет управляемые объекты, но получить полный
  корректный ответ не удалось. Не определяй это только по HTTP-методу или replay_safe:
  идемпотентная мутация тоже может быть replay_safe. Верни явный error и диагностику
  неполноты; evidence=[], pending=false, done=false, success=null. Это завершённая
  неудачная попытка чтения, а не подтверждение получения данных или эффекта в мире.
  Ядро сохранит её с прежним request_id, остановит пакет и вернёт ошибку модели.
  Следующий запрос, его параметры и необходимость чтения выбирает модель; нельзя
  менять payload старого request_id. Неполный ответ не становится полными данными.
  Для действия, которое могло изменить мир или начать операцию, используй unknown.
- evidence — фактически завершённые действия/операции, эффекты или итог мира:
  `{"identity":"стабильный ID события","outcome":"success|failure",`
  `"kind":"action|operation|effect|completion","detail":"что фактически наблюдалось"}`.
  detail может быть строкой или JSON-объектом с фактическими данными результата.
  При повторном наблюдении того же события identity НЕ меняется. Не выдавай чтение
  или принятую операцию за успешное выполнение. Не выдумывай identity из времени
  опроса. API-успех и улучшение целевой метрики — разные утверждения.
  При этом измеренный исход диагностического испытания объекта тоже является
  фактом: управляющая мутация для этого не обязательна. Если действие действительно
  испытало объект и вернуло его измеренный успех/отказ, отражай именно этот исход
  как effect со стабильным ID данного испытания или его request_id. Успешная
  доставка диагностического запроса не превращает отказ испытуемого объекта
  в outcome=success. Чтение справочника само по себе такого факта не создаёт.
  Не подавляй повторную выдачу завершённых событий флагом «уже доставлено»:
  процесс мог завершиться до сохранения результата ядром. Дедупликацию делает память.
- Переданный request_id сохраняй при всех повторах одной мутации. Для нескольких
  запросов внутри одного действия используй стабильные суффиксы и локальный журнал.
  Не повторяй мутацию с неизвестным исходом, если API не гарантирует идемпотентность.
  Обычное action — один удалённый управляющий запрос с вспомогательными чтениями.
  Параметризованный скил может исполнить явно переданную моделью последовательность.
  План и стабильные дочерние request_id сохраняй до отправки; каждый полученный
  результат записывай до следующего шага. Проверяй заданные предусловия и завершение
  зависимостей; при ошибке или неизвестном исходе остановись. Если общего бюджета
  вызова недостаточно, верни pending и идентификатор продолжения. Отдельное act
  может продолжить тот же сохранённый план с прежними дочерними request_id;
  observe по-прежнему не выполняет управляющие действия. Не создавай новые
  управляющие запросы ради восстановления потерянного ответа.
- После сбоя процесс будет создан заново: загружай сохранённое состояние и bootstrap.
  Сохраняй полученные IDs/секреты сразу; не требуй прошлого контекста Python-процесса.
- Секреты считывай из bootstrap/ответов сервера внутри скрипта. В data, evidence,
  metrics и error заменяй их на `[private]`. Не включай секреты в исходники или промпты.
- HTTP: ограничивай время ожидания и объём ответа. Обрабатывай ошибки протокола;
  не считай частичный JSON или HTML успешным ответом. Будь готов к корректному JSON
  на keep-alive соединении без немедленного EOF.
  Для JSON используй response.read1() небольшими порциями и json.loads() после
  каждой порции; верни результат сразу при полном JSON. Не используй read(N)
  с большим N: некоторые серверы продолжают держать соединение после документа.
  Стабильную документацию кешируй с метаданными источника и явным способом обновления.
  Недоступный справочник не должен задерживать каждое наблюдение, если уже есть
  пригодная сохранённая версия. Указывай, что данные взяты из кеша, и их свежесть.
- В sandbox доступны Python stdlib, системные бинарники и сеть. Не устанавливай пакеты.
  Не запускай фоновые процессы: по завершении вызова они будут остановлены.

Минимальные артефакты: `scripts/adapter.py`, `skills/operate/SKILL.md` с YAML
name/description, `prompts/world.md`. Скил объясняет вызовы action, промпт — цель
и правила мира из его документации. Полные спецификации храни в references/.
Пиши компактно: для простой интеграции обычно достаточно одного небольшого
скрипта. Не добавляй поиск неподтверждённых endpoint, кеши и универсальные обходы
схем, если доступная документация их не требует.
