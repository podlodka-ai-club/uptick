# Устойчивые чтения каталога, ресурсов и метрик

Эти действия только читают данные и не запускают операции.

## Каталог команд

```json
{"kind":"command_catalog.get","mode":"cache_preferred","timeout_seconds":15,"budget_seconds":30}
```

Каталог является авторитетным источником имён команд и их параметров. Перед мутацией сервера прочитайте актуальную схему команды. Для удаления передавайте только точный `server_id`, полученный из свежего каталога ресурсов, и остальные поля, которые явно требует схема. Не угадывайте имя команды или поля.

Если сеть недоступна, пригодная кешированная копия может быть возвращена с метаданными источника и свежести. Ошибка без полного каталога не означает, что неподтверждённая схема допустима.

## Полный список ресурсов

```json
{"kind":"resources.get","timeout_seconds":15,"budget_seconds":45,"max_pages":100}
```

`resources.get` должен обходить документированную пагинацию до конца либо явно сообщать, что результат неполон. Для решений о серверах используйте свежие записи с точными `id`, `type`, `capacity`, `hourly_cost` и `status`. Не считайте первую страницу полным или текущим состоянием при наличии курсора продолжения.

## Проверка операции

После принятой мутации сохраните возвращённый `operation_id` и проверяйте именно его:

```json
{"kind":"operation.get","operation_id":"<operation_id>"}
```

`pending=true` означает только продолжающуюся операцию. Завершение подтверждается терминальным статусом и стабильным evidence от адаптера. Не отправляйте новую мутацию для восстановления потерянного ответа.

## Временной ряд метрик

`metrics.get` передаёт параметры запроса согласно актуальной OpenAPI-схеме:

```json
{"kind":"metrics.get","params":{"from":"<simulation-time>","to":"<simulation-time>","step_seconds":300}}
```

Названия параметров диапазона и шага должны совпадать с каталогом API конкретного мира. Границы задаются во времени симуляции, не во времени локальной машины. Пустой свежий `series` — фактический ответ источника; он не доказывает отсутствие периодичности вне запрошенного диапазона. Транспортная ошибка или некорректный ответ возвращаются как `delivery=read_failed`, поэтому основной цикл сам выбирает новый запрос и не переиспользует старый payload.
