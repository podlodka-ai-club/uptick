# Устойчивое чтение каталога, ресурсов и метрик

## Каталог команд

`act` поддерживает локальное read-only действие:

```json
{"kind":"catalog.get"}
```

Оно возвращает полный `commands_markdown` из ответа запуска:

```json
{
  "data": {
    "command_catalog": {
      "commands_markdown": "...",
      "source": "bootstrap.commands_markdown",
      "freshness": "stable_for_run"
    }
  },
  "evidence": [],
  "delivery": "known"
}
```

Этот документ является стабильной спецификацией API для запуска и содержит точные схемы допустимых команд, включая мутации серверов и проверку асинхронных операций. Он не зависит от доступности сетевого источника `command_catalog`. Если документа нет или он некорректен, действие завершается как `delivery=read_failed` с явной ошибкой.

При автоматическом `observe` таймаут источника `command_catalog` допускает один дополнительный безопасный повтор всего read-only наблюдения. Повтор не выполняет управляющих действий. Если источник снова недоступен, наблюдение остаётся частичным и сохраняет диагностику.

## Ресурсы

Для актуального состояния используйте существующее read-only действие `resources.get`, описанное в основном скиле. Запрашивайте страницы до явного признака завершения и не считайте первую страницу полным инвентарём. Полный результат должен содержать для каждого сервера как минимум точный `server_id`, тип, capacity, hourly_cost и текущий статус.

Перед удалением сервера:

1. Получите свежий полный инвентарь через `resources.get`.
2. Выберите точный `server_id` в модели.
3. Получите точную схему команды удаления через `catalog.get`.
4. Передайте серверу ровно выбранный ID; адаптер не выбирает объект самостоятельно.
5. Если команда принята асинхронно, сохраните `operation_id` и проверяйте её существующим интерфейсом операций. Принятие не является завершением.

Неполная страница или ошибка одной из страниц не является полным снимком и должна возвращаться как ошибка чтения, а не как подтверждение отсутствия серверов.

## Временной ряд метрик

Автоматический снимок в `observe` предназначен для текущего состояния; пустой `metrics.series` не доказывает отсутствие периодичности нагрузки.

Чтобы исследовать прошедший период, сначала вызовите `catalog.get` и используйте точную опубликованную схему серверной команды `metrics.get`. Модель должна явно задать:

- начало диапазона в simulation-time;
- конец диапазона в simulation-time;
- поддерживаемый сервером шаг или агрегацию;
- при наличии пагинации — продолжать чтение до полного диапазона.

Не подставляйте wall-clock time вместо simulation-time. Не выдумывайте имена параметров: они берутся из возвращённого `commands_markdown`, поскольку серверная схема является источником истины. Если полный корректный ряд получить не удалось, read-only запрос должен завершиться с `delivery=read_failed`, `evidence=[]` и диагностикой неполноты; частичный ряд нельзя выдавать за полный.
