# Что показать на хакатоне

Главная история: **агент учится решать, какой опыт заслуживает доверия.**
Ему не нужно помнить каждый HTTP-запрос всю жизнь. Важно сохранить цель,
незавершённую работу и несколько проверенных уроков, которые меняют решения.

## 1. Начать с результата

```bash
cd /Users/aigizk/projects/uptick/ak-agent
./run.sh report
```

Выбрать `run_id` и открыть его в существующем дашборде симулятора. Смотреть
одновременно на завершённость, SLO и стоимость. Незавершённый мир с текущими
99% ещё не является победой. Реальные результаты и ограничения сравнения
сохранены в [EXPERIMENTS.md](EXPERIMENTS.md).

## 2. Дать слово агенту

```bash
./run.sh ask "Расскажи три главных урока. Какой совет ты пересмотрел после ошибки? Приведи основания и скажи, что пока не доказано."
./run.sh memory
```

Это новый вызов Codex SDK со снимком SQLite, а не заготовленный текст выступления.
За рассказом можно показать счётчики: `support`, `against`, `uses`, уровень памяти
и ссылки на эпизоды. `uses` означает заявленное моделью применение урока;
само по себе оно не доказывает улучшение результата.

В первых экспериментах возник показательный урок: удачная моментальная проверка
после уменьшения числа серверов не гарантировала устойчивость. Через 38 секунд
возникли новые ошибки. Агент записал противоречие и уточнил условие применения
совета. Это пример изменения памяти по опыту, а не замена весов модели.

Отдельно сохранена [цепочка обучения между двумя мирами](experiments/learning-trace.json):
финальные метрики → самооценка стоимости → принятый урок → решение другого run,
которое использовало этот урок. В файле реальные записи, а не демонстрационная фикстура.

## 3. Показать потерю процесса без потери задачи

```bash
./run.sh run --seed 43 --max-steps 3
# Процесс завершился по бюджету решений; игровой run ещё не завершён.
./run.sh resume --max-steps 5
```

В выводе остаётся тот же `run_id`. Агент получает сохранённую цель, план,
неоконченные операции и последние результаты. `run` создаёт новый мир, seed можно
повторять; `resume` продолжает прежний мир. Реальное время симулятор продолжает учитывать.

## 4. Объяснить память за полминуты

«Паспорт хранит цель и правила. Рабочая память хранит то, что я делаю сейчас.
Эпизоды — это недавний опыт. Повторные независимые подтверждения превращают
гипотезу в устойчивый урок, а последовательность шагов — в навык. Ошибка ослабляет
доверие и помогает уточнить правило. Старый слабый опыт постепенно забывается».

В коде это одна SQLite-база и простой счётчик подтверждений. Не нужно объяснять
векторную базу, граф знаний или обучение нейросети. Фактическое забывание в живом
прогоне видно в `memory`; если счётчик равен нулю, нельзя говорить, что оно уже
произошло. Сам механизм отдельно проверен автоматическим тестом.

## 5. Показать, как проверяется польза памяти

```bash
./run.sh evaluate --seeds 201,202 --jobs 2
```

Для каждого нового seed запускаются два мира: с замороженными уроками и без
них. Во время проверки оба агента не учатся. Это длительный эксперимент;
для короткого выступления лучше заранее подготовить его результаты. Один удачный
мир не доказывает, что память всегда полезна, и ошибка API не считается поражением
одного из агентов.

Последняя фраза выступления: «Мы сохраняем не все действия подряд, а опыт,
который выдерживает повторную проверку. И можем показать, почему агент ему верит».
