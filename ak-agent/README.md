# AK Agent: опыт переживает перезапуск

Автономный CLI-агент для SRE-симулятора API v2. Codex SDK через подписку ChatGPT
выбирает действия. SQLite хранит цель, состояние, проверенные уроки и навыки.
Агент получает поток ситуаций из симулятора и работает по циклу:

**увидел → решил → выполнил → проверил → запомнил или пересмотрел урок.**

Цель приходит от самого симулятора: завершить игровую неделю с uptime ≥ 99%
при минимальной стоимости инфраструктуры. `slo_passed` считается итогом только
после завершения run. Успешный HTTP-запрос к панели ещё не означает достижение цели.

## Быстрый запуск

Нужны macOS/Linux, Python 3.12+, `uv`, интернет и вход в Codex через ChatGPT.

```bash
cd /Users/aigizk/projects/uptick/ak-agent

# Проверить авторизацию. Если входа нет — ./run.sh --login
./run.sh --check-auth

# Новый мир; seed обязательно положительный
./run.sh run --seed 42
```

`run.sh` устанавливает зависимости по `uv.lock`. Он исключает API-ключи из
окружения дочернего процесса; SDK дополнительно проверяет тип аккаунта `chatgpt`.
Авторизацией управляет SDK; код агента самостоятельно не читает и не копирует
`auth.json`. Для входа на сервере также можно
использовать `codex login --device-auth`, если он доступен аккаунту.

В строке `started` выводятся `run_id` для дашборда симулятора и `local_id`
для восстановления. Дальше CLI показывает состояние, решение, использованную
память, результат команды и новые уроки в JSONL. Дашборд — у симулятора.

```bash
# Ctrl+C сохраняет возможность продолжить. Продолжить последний run:
./run.sh resume

# Или указать local_id / run_id из вывода:
./run.sh resume ak-ВАШ_ID

# Посмотреть уроки без обращения к LLM:
./run.sh memory

# Попросить агента рассказать о своём опыте:
./run.sh ask "Что ты запомнил и какие решения изменил благодаря этому?"
./run.sh ask "Какие уроки пока ненадёжны? Какие ошибки ты перестал повторять?"

# Результаты запусков:
./run.sh report
```

У каждого запуска есть бюджет решений: по умолчанию 250. Если он исчерпан,
run остаётся доступным через `resume`; это не успешное завершение симуляции.
Например, для демонстрации восстановления:

```bash
./run.sh run --seed 43 --max-steps 3
./run.sh memory
./run.sh resume --max-steps 250
```

Симулятор учитывает реальное время между запросами. Сохранение позволяет
продолжить управление, но не замораживает игровой мир на время остановки агента.

## Где память

По умолчанию: `ak-agent/.local/agent.sqlite3`. Путь не зависит от текущей папки
терминала. Можно передать `--memory /путь/agent.sqlite3` каждой команде или задать
`AK_MEMORY`. Папка `.local/` исключена из Git. Файл SQLite имеет права `0600`:
он содержит также игровые данные доступа к текущим run.

SQLite использует WAL: для копирования живой базы нужен SQLite backup, а не
копирование одного файла без соседних `-wal`/`-shm`. Закрытую базу можно переносить
вместе с агентом; вход Codex на другой машине выполняется отдельно.

| Уровень | Что хранится | Как меняется |
| --- | --- | --- |
| Паспорт | Полученный протокол, каталог, цель, идентификатор мира | Записывается сразу после получения; не забывается во время задачи |
| Рабочая память | План, наблюдения, незавершённые операции, очередь действий | Обновляется после решения и каждого действия |
| Эпизоды | Наблюдение, действие, результат, оценка, время LLM | Последние 150 эпизодов на run |
| Уроки | Условие применимости, вывод, теги, подтверждения и противоречия | Новые доказательства укрепляют или ослабляют вывод |
| Навыки | Последовательность с проверкой результата | Процедура становится навыком после ≥ 3 подтверждений при доверии ≥ 75% |

Доверие = `(подтверждения + 1) / (подтверждения + противоречия + 2)`.
Это счётчик доказательств, **не откалиброванная вероятность успеха**.
Один эпизод — максимум одно подтверждение урока. Повторное чтение той же операции
не считается новым опытом. HTTP 202 не подтверждает выполнение. Ошибка может
подтвердить урок о том, как избежать этой ошибки, но не успех исправления.
LLM интерпретирует последствия; код проверяет существование и тип доказательств.
Интерпретация LLM всё равно может ошибаться — поэтому у уроков есть противоречия,
условия применения и видимые основания.

При каждом обучающем решении проходит один цикл консолидации. Сила урока
экспоненциально уменьшается с числом циклов без новых подтверждений. Период
полураспада = `30 + 20 × подтверждения + 100 × важность`. Слабые неважные уроки
с силой < 0.12 забываются. Остаётся максимум 80 уроков, 100 завершённых запусков
и ограниченный журнал запросов. Повторное извлечение само по себе не усиливает
память: агент не может убедить себя в правоте, перечитывая собственный текст.

Незавершённые задачи сохраняются для `resume`. Ограничения памяти относятся к
одной базе; отдельные архивы проверочных экспериментов и перенаправленные
пользователем консольные логи автоматически не удаляются.

При поиске учитываются совпадения слов и тегов, сила и важность. В решение
попадает максимум 8 уроков. Поле `used_memory` показывает, какие из них модель
заявила как использованные; это объяснение модели, а не доказательство причинности.
Её проверяет отдельный эксперимент с отключённой памятью.

Навыки — короткие текстовые процедуры. Модель выбирает подходящий навык и
подставляет текущие данные в действия. Проект не исполняет сгенерированный
Python или shell. Параметры API и `request_id` проверяет транспорт.

## Обучение и эксперименты

```bash
# Поток миров последовательно: следующий получает накопленный опыт
./run.sh train --seeds 11,12,13

# Два мира одновременно, общая память через SQLite WAL
./run.sh train --seeds 21,22,23,24 --jobs 2

# Сравнить доступные модели на пробных мирах
./run.sh models
./run.sh train --seeds 31,32 --models gpt-5.6-sol,gpt-5.6-luna --jobs 2

# Подсказка для исследования остаётся решением LLM
./run.sh train --seeds 41,44 --strategy "Изучи, какие наблюдения позволяют реже обращаться к LLM без ухудшения результата"

# Проверить пользу памяти на новых, не обучающих seed
./run.sh evaluate --seeds 101,102 --jobs 2
```

`train` запускает независимых агентов, по одному Codex-клиенту на мир, и собирает
их опыт. Это обучение внешней памяти, без изменения весов LLM. Общая память
позволяет обмениваться уроками, поэтому сравнение моделей в `train` является
исследовательским, а не контролируемым бенчмарком.

В `train`/`evaluate` Ctrl+C останавливает работников после текущих вызовов и
сохраняет неисполненную очередь. Ещё не начавшиеся миры отменяются. В отчёте
остаются ID для продолжения каждого начатого run через `resume`.

`evaluate` замораживает уроки перед стартом. Для каждого seed и модели создаёт
два изолированных run: с памятью и без неё. Обучение в обоих отключено; паспорт
и восстановление сохраняются. Обучающие seed отклоняются. Сравниваются
завершённость, uptime, стоимость, количество решений и суммарное время LLM.
Одинаковый seed не устраняет вариативность LLM и влияние реального времени —
для убедительного вывода нужны несколько проверочных миров и повторов.

Отчёт: `.local/train-*/results.json` или `.local/evaluate-*/results.json`.
У проверочных run свои базы в папке эксперимента; продолжать такой run нужно с
`resume --memory ПУТЬ_К_ЕГО_БАЗЕ`. Ошибка сети или Codex сохраняет checkpoint и
отражается в отчёте, не считается успехом симулятора.

Модель по умолчанию — `gpt-5.6-sol`, effort `low`; каждые 8 решений и в конце
run агент делает более внимательный пересмотр с effort `medium`. Переопределение:
`--model`, `--effort`, `CODEX_MODEL`. Доступность модели определяется подпиской.
SDK использует установленный `codex`, если он найден; иначе — свой runtime.
Путь к бинарному файлу можно задать через `CODEX_BIN`.

## Как устроен код

- `brain.py` — Codex SDK, короткие объяснения и структурированные решения.
- `simulator.py` — HTTP, авторизация, проверка параметров, идемпотентные повторы.
- `memory.py` — SQLite, поиск, подтверждение, пересмотр и забывание опыта.
- `agent.py` — цикл, наблюдения и восстановление очереди действий.
- `commands.py` — CLI, параллельные эксперименты и отчёты.

В коде нет дерева «если диск полон — очистить; если нагрузка — добавить сервер».
Модель узнаёт протокол от симулятора и выбирает действия. Автоматизированы
наблюдения, доставка команд, проверка формата и учёт памяти. Перед каждой мутацией
записываются намерение и стабильный `request_id`; после сбоя запрос повторяется
с тем же ID. Пакет приостанавливается на объявленной зависимости; статус
асинхронной операции попадает в следующее наблюдение для решения модели.
Один run защищён от управления двумя процессами локальной блокировкой.

Контекст Codex пересоздаётся каждые 10 решений: агент умеет продолжать, опираясь
на SQLite. Смена модели при `resume` также допустима.

Независимые операции модель может отправлять пакетом: например, подготовить
несколько ресурсов одновременно. Для одинаковых независимых команд есть
`repeat_count`: LLM выбирает количество, исполнитель разворачивает очередь
с отдельным `request_id` для каждого повтора. Максимум 64 исполнения за решение.
Это сокращает размер ответа LLM при массовом создании ресурсов.
Зависимость отмечается явно через
`wait_for_completion`. HTTP-запросы одного run последовательны, потому что
симулятор возвращает `CONCURRENT_RUN_REQUEST` при их одновременном исполнении.

Транспорт читает JSON порциями и принимает только полностью разобранный объект.
В живых прогонах иногда приходила лишь часть большого HTTP-ответа, после чего
чтение зависало; причина не установлена. При потере неполного ответа
запрос повторяется с тем же ID. Недоступная телеметрия помечается как недоступная;
она не подменяется пустой выборкой без ошибок. Без свежего overview агент останавливается.
Пять повторных `INTERNAL_ERROR` на одном действии останавливают запуск с
`runner_status=blocked`: это внутренняя ошибка API, а не отрицательная оценка SRE.
После исправления симулятора можно выполнить `resume`.

## Тесты и демонстрация

```bash
uv run --locked python -m unittest discover -s tests -v
```

Тесты проверяют рестарт, повтор потерянного ответа, блокировку одного run,
зависимости async-операций, ложные подтверждения, учёт ошибок, противоречия,
забывание, ограничения памяти, секреты и авторизацию по подписке.

Для показа: запустить мир → увидеть инцидент и решение → `ask` о памяти →
перезапустить процесс → продолжить run → показать сравнительный `evaluate`.
Рассказывать об улучшении стоит по результатам, включая неудачные миры.
